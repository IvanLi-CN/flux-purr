# 3A 合同修正与应用后加热复核

## 范围与证据边界

验收对象是标定结果应用后的正常自动加热。标定采集、保存成功和正常加热性能分别判定，模拟报告截图只证明显示。风扇模型及正常风扇策略保持原状。

源码基线为 `d649f34d34d4880d5a25145ecabe9c8a191bc5f2`；待审查候选包含工作树改动，不能只用基线 SHA 代表产物。实际烧录 ELF SHA-256 为 `0bcdda0286459b978cf9a233518a94b09665ef6e2c402e2089b7664515742816`，产品镜像大小为 2,062,464 bytes。精确授权端口为 `/dev/cu.usbmodem21141401`；经仓库 devd 操作，按 owner 授权跳过 EEPROM 备份。

## 60W 来源与电流下降原因

提交 `03e9f04f7c9261edba3ca18e4dd3f41df919c3d4` 将测试工具的 3A 默认源功率设置为 60W。固件把 Fixed PDO 的 `20V × 3A` 推导为 PPS 总功率限制，限制常规扫描至 20V，并按该数值生成 `21V / 2.85A` 终点；正常加热又采纳这个降流终点。它不是 3A 方案应有的规则。

OvO `856a141cdbd4` 的实机配置也保存着 `power_watts=60`。修正后的 Flux Purr 在 21V 始终申请 3000mA，但源端 TPS 读回限流为 2800mA，实际约 2.77A。这是设备申请电流与电源内部限流的两件事，不能以“申请 3A”证明实际供电没有被限制。

owner 明确授权后，将 OvO 功率能力字段由 60 改为 65；前后完整配置比较只有 `/capability/power_watts` 改变，`pps3_limit_ma=3000`、`pd_pps_5a=false` 和其他配置相同。65 是这台源覆盖 `21V × 3A` 的能力配置，不作为 Flux Purr 3A 方案的功率上限。CLI 默认不会再把源写回 60W。

## 低温采集与扫描终止原因

首次连续扫描在探测电压的同时持续升温，低温观测不足；较宽分桶还会让后续点替换早期记录。冷态扫描改为先空载稳定 500ms，再确认至少 200ms 的连续带载数据；后续每 5°C 重探，独立保留首次恢复后的稳定边界点。空载数据不能成为安全电压证明。

第一版修正候选的实测暴露另一分支：热端两次探测失败后，扫描在低于 APDO 上限的位置提前完成，导致后续继续升温时固定在偏低电压。该次标定主动取消，旧 active 保留。修正后重复失败只进入恢复与后续重探，不能提前宣告达到电源上限。

## 完整温区标定与持久化

有效标定从约 29.70°C 启动，实时采样最高 220.37°C，随后停止加热并自然冷却到 80°C 以下。固件终态为 `completed`，冻结耗时 449900ms，保留 48 个热轨迹点和 31 个供电边界点；active 事务为 `1347840305`。

该标定发生于源功率能力仍为 60 的配置，不能作为修正源配置后的正常加热合格证明。改变源配置引发重新上电后，原 active 事务和边界从 EEPROM 成功恢复；attempt 为空是重启后的协议状态，不应导致读取失败或伪造新 attempt。

修正源配置后，使用相同 ELF 再次从 29.99°C 完成完整标定，终态 `completed`、耗时 437050ms，48 个轨迹点、30 个供电边界点，active 事务为 `1348167743`。原始同步记录最高温度为 220.15°C，输入功率峰值为 61.143W。该结果作为正常加热复测的模型基线；前一事务不与此试验混用。

## 正常自动加热验收

从不高于 30°C 且 60 秒温度斜率绝对值不超过 0.01°C/s 的冷态开始；使用已经持久化的 active 模型，通过 runtime 命令启用正常自动加热至 220°C，不启动标定或调优。

同步记录温度、申请电压、合同电流、逻辑输出、物理输出及 OvO 实测电压、电流、功率和内部限流。原始采样保留双方时间，关联时限定接收时间差不超过 1 秒并去除源端重复时间戳；这不等同于硬件同步测量。

验收包括 30°C 与 60°C 附近的实际电流、达到 21V 前是否接近 3A、20→21V 是否人为降流、完整温升与 Hold 稳定性。任何加热中的非 3000mA PPS 合同、保护故障、传感器故障或超过时间界限均保留为失败，不降低质量门槛。

冷态正常加热约 1.016 秒、32.21°C 时，13V 合同下源端实际为 12.751V / 2.931A。30°C ±5°C 的稳定带载样本为 2.930–2.933A；60°C ±5°C 为 2.820–2.899A，中位数为 2.859A。加热中的合同始终为 3000mA。稳定区间要求前一秒连续满导通、申请与合同及源端目标电压一致；原始卸载与切换采样保留，不混入稳定电流范围。

冷态运行在约 107.8 秒、134.7°C 时中断。08:16:21 UTC 附近，源端从 18V PPS 回到 5V Fixed，随即检测到授权串口消失。中断前源端实际约 17.814V / 2.928A / 52.165W，未报告 SW2303/TPS 锁存故障。owner 确认没有手动断电、插拔或 HUB 操作。端口硬门禁触发后停止 MCU 操作；经再次明确授权，在同一端口读回 `chip_power_on` 和归零后的 uptime，加热关闭、物理输出为零，active 事务及边界和 ADC 配置不变。该事件是自发重新上电的证据，不足以判定故障发起方。

后续从约 40.25°C 做正常自动加热故障复现，保持同一模型、3A 源配置及风扇设置，不作为冷态验收。该轮未重现复位，300 秒时仍为 Warmup，最高温度约 180.58°C；后段申请 20.5V，实际电流约 2.924A、输入功率最高约 59.57W，逻辑与物理加热均为 100%。达到 300 秒后停止加热并读回物理输出为零，原目标恢复，模型、边界和 ADC 配置未变。未进入 Approach/Hold，不赋予这两个阶段或 220°C 的资格。

第二轮温态故障复现增加完整 status 采集，共记录 912 条设备状态。该轮未发生复位，也未采到非空 PD 协议故障字段；300 秒仍处于 Warmup，最高 183.1°C，后段申请 21V / 3000mA，稳定带载输入功率最高约 59.48W。采样没有覆盖快速电源瞬态，未重现不等于排除首次故障。结束后加热关闭、物理输出为零、目标恢复为 150°C，active 模型、供电边界和 ADC 配置均未改变。

因此低温电流改善与 3A 供电合同已经取得实测依据，但冷态完整热目标、正常加热 21V 终点及自发重新上电原因仍未完成验收。不能把温态复现的片段拼接成完整冷态成功，也不能把这次温态试验的最高温度当作硬件物理上限。

## 回归验证

固件 host all-targets 共 1258 项测试通过；严格 host 与 Xtensa clippy、完整产品构建、无网络构建和启动栈检查通过。devd 全套测试通过，包含超过 60W 不被错误拒绝和 2850mA 合同被判为失败的回归。EEPROM 格式和旧数据解码保持兼容，旧降流终点不被正常 3A 运行时选用。
