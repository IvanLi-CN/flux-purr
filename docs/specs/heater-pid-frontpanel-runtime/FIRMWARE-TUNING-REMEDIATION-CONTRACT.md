## 整改项与验收

自然冷却数据参与生产控制、风扇样本与标准报告图表、Hold 恢复及搜索停滞处理按 [自然冷却控制合同](NATURAL-COOLING-CONTROL.md) 执行。这是获准的生产控制与内部策略差异；原始冻结外部 runner 不改变，旧的每帧0.05°C滑行恢复要求由真实时间窗口替代。固件全部目标的失败评分与有界搜索允许按完整稳定进展、整段越带事实及尚有余量的有效参数处理，低温内部搜索不再要求与冻结外部策略逐值一致；高温高侧分支的既有边界仍保留。初值只用新标定与生产常量，随后只用本轮反馈，不导入历史调优。固定物理交接、条件延长前提、3°C热指标、独立60秒确认及保存门禁继续有效。

### Approach 轨迹与阶段边界

Warmup保持独立全功率及100ms物理软启动。Warmup→Approach首个请求立即为50‰；随后每周期跟踪独立生成的期望温度与升温率轨迹，不按标定延迟固定等待，也不把温度下降确认作为恢复供热的必要条件。轨迹使用新标定的自然损失、热容量、传热延迟、实际源能力及候选响应参数，正常逻辑请求约束50..1000‰，保留的profile floor/ceiling不钳制它。已施加VIN、物理MOS占空比及电阻曲线估算的供热按真实时间保存，预测供热到达时的温度与升温率；该估计不是电功率实测。模型前馈与同一未来时刻的温度/升温率跟踪误差共同决定新请求。保护仍可立即停热，普通predictive coast不得把Approach置零。Hold参考为最终恒定目标，沿用现有受保护PI。实际温度仍决定固定物理Hold入口与验收；原稳定窗口、条件延长、独立60秒确认和PD/PPS策略保持不变。 交接制动修正及未观测Hold的搜索边界保持有效，公式与生命周期见[自然冷却控制合同](NATURAL-COOLING-CONTROL.md)。

模型制动控制使用timing policy `4`，绑定 `modelApproachFloorPermille=50`、`allowedApproachFloorPermille=50` 和生产有效下限 `50‰`。候选配置值如实记录，不能抬高实际模型下限。原期限首次检查时仍须处于Approach、尚无期限内有效稳定窗口、期限前取得真实50‰请求且之后未提高非零请求，才可按原有限上限延长。期限、稳定窗口、热指标和独立确认均不放宽。历史policy `3` 保留100‰模型规则，policy `2` 保留100‰配置/Hold派生规则，不能以新政策重写旧报告。

初始Approach制动只累计稳定PPS档内相邻已接受采样的有符号降温量和真实间隔；变暖抵扣累计量，高于本档参考温度超过0.05°C清除全部证据。PPS切换开始及稳定边界重建温度原点、丢弃待计算间隔、负斜率与确认次数，只有正在加热、模型有效且初始制动尚有剩余时间时保留此前已验证的档内量。新档首样本、等待、拒绝采样及跨档读数差均不计降温或时间。累计有效降温>0.15°C、有效时间≥100ms后，当前档仍需重新连续两次接受下降观察且滤波斜率≤−0.02°C/s才提前模型补热。真正传感器恢复、目标切换、停热、退出阶段与故障清空全部证据；Hold滑行恢复不采用档间累计。传热延迟到期、5%入口、5..100%模型请求、PD/PPS策略和全部资格门禁保持原义。不能用切换偏移伪造下降，也不能因反复切换抹掉已验证档内事实。

### R1：核对完整旧方案一致性

- 将初始 seed 选择、插值、候选变换、scout/confirm 输入投影、score、gate、预算、重试和 accepted-target blocking 逐项对照锁定基线。
- 分别列出冻结基线、当前分支外部 runner、当前固件的差异；当前分支两个实现相同，不能证明与冻结基线相同。
- 对 scout 超时后的证据范围与固件硬停止保留的样本前缀单独说明；不得用固件停止后的样本证明固件当时已经满足门槛。
- 差异必须归为已获准边界、实现缺陷或待研判设计变更。未经研判不得把修改外部 runner 当成恢复一致性的方法。

验收：每个差异都有固定基线、同一输入、字段级输出比较和处置依据。正常、低侧 miss、高侧越带、稳定窗口中断、缺失 qualified Hold、确认失败、预算耗尽及区间阻断均有覆盖。修正后仍存在的有意差异必须明确列出，不声称全向量一致。

### R2：修正 Approach 候选搜索与交接证据

- 分别记录候选配置、控制律、生产effective floor和真实请求。有效制动模型下限固定为50‰；历史policy 3为100‰，历史或无模型profile路径按原Hold派生规则核验。
- 普通调优不搜索全程零功率Approach。进入Approach立即以50‰制动；后续补热受同一正常下限约束，真实保护关断始终优先。
- 高侧余热、低侧缺口和 Hold 波动按完整证据分别修正。需要减少储热时，审查预热退出位置、brake/lead、模型剩余能量与 damping 的联合影响；保留字段 floor/ceiling 的变化不能被当成模型输出必然变化的证据。不得忽略交接及其它参数而把所有失败归为单一功率不足，也不能为了绕过期限放宽 Hold 入口。实验须保持可归因性，不在同一次失败中无差别搜索全部字段。
- 模型轨迹已在原时限内完成物理Hold、高输出维持后低侧离带时，搜索优先修正有余量的Hold基线/reheat及恢复提前量，而不是继续改变Approach。此内部变换要求完整正常Approach和已观测Hold、高输出分位及低侧温度证据，按[自然冷却控制合同](NATURAL-COOLING-CONTROL.md)的限定范围执行；缺失Hold、高侧、保护与非热故障不适用。生产Hold控制律、PD/PPS、原期限和独立确认保持不变。
- 低温试验已经进入稳定带、随后从高侧退出且Hold全程停热或仅有入口脉冲时，Approach的完整正常请求范围与中位数共同判定低供热余热失败。请求全程不超过100‰，或正常范围内的请求中位数不超过100‰，均优先按观测过冲提前Warmup交接；短暂补热峰值不得独自将它归为持续供热过高而只增加阻尼。持续高于该中位数的Approach仍沿用阻尼修正。此100‰仅是搜索失败分类，不是控制器下限、上限或新验收门槛；正常Approach仍为50..1000‰。
- 满足同一严格停热Hold/正常Approach证据的低温过冲>3°C，也优先使用既有制动距离修正，不受100‰中位数分类限制；较小过冲保留原分类。严重停热上冲证明交接前供热需减少，不能单凭中位数略高于分类值只调整阻尼。此内部搜索例外不改变控制下限、阶段入口、条件延长或资格门槛。
- firmware engine 的 `160/180/220/240°C` 目标采用获准的高侧减能例外：原始温度事实证明进入稳定带后从高侧离开，或期限时未进入稳定带且位于高侧，且存在未验证窗口的 full-speed-to-stable 失败，或过冲、qualified Hold 峰峰值、入口余热任一超过 `3°C`，须优先使用既有保守减能变换。稳定门槛失败不要求同时超过独立的 `3°C` 热指标；已验证窗口后的普通离带不能单独触发这一例外。该规则覆盖 scout、batch 与独立确认失败后的候选生成；不能被 `Underpowered` 曲线标签覆盖。普通严重度下 Approach 配置 floor/ceiling 各减 `100‰`，Hold/reheat 基线各减 `50‰`，brake 加 `3°C`，仍使用既有边界、截止和 PI 约束；严重度至少 `20°C` 时保留既有 `180‰`/`5°C` 有界变换。历史或无模型 profile 路径的 effective floor 取配置 floor、Hold 基线及生产下限的最大值；有效模型policy 4路径固定为独立的 `50‰`，保留字段变化本身不改变模型输出。保守变换中的 holdEntry/holdExit 只改变曲线参数，不改变物理 Hold 入口。低侧失败、无高侧证据或安全故障不适用该例外；外部 runner 和 `<=150°C` 规则保持冻结。这是候选策略的有意差异，不能声称该输入与旧方案逐值一致。
- 继续使用同一生产控制器。`holdEntryCentiC` 保留 Approach 曲线、预测 coast 与输出 blend 的参数作用，但与阶段入口解耦。普通 5A 加热和固件调优的 Approach→Hold 均要求真实温度达到目标减 `0.5°C` 且处于目标 `±3°C` 内，与既有 qualified Hold 物理判定共用真相源；候选、超时与预测温度均不能绕过该入口。不增加新的升温率或剩余储热阈值；这些额外交接门禁与控制公式更改仍须单独研判。
- Hold 控制 phase、qualified Hold 起点和稳定窗口必须分别认定；不得将提前进入控制器 Hold 作为物理温度已经达标的证据。

验收：全部历史 trial 的分类、有效参数与下一候选可复核；预期降低 Approach 能量的候选确实通过 preview 驱动相应逻辑请求。低侧失败不误走高侧保守分支，缺失 Hold 指标不被当成零波动，没有强制时间切换伪造达标。通过要求由 R4 判定。

高温例外还须覆盖高/低侧差分回放、确认失败与安全拒绝；同提交固件完成 160°C 诊断及完整九目标 HIL，候选身份和实际 effective floor 可复核。策略分支命中不等于短试验或独立确认已经通过。

### R3：实现有条件的 Approach 延长

只有同时满足以下两个产品前提，才具备延长资格：

1. 当前模型policy 4的实际控制律下限与生产有效下限均为50‰，且原期限前真实Approach请求已达到50‰。历史policy 3仍为100‰模型下限，policy 2仍绑定100‰配置与有效下限。
2. 原期限首次控制周期检查时仍在 Approach，且尚未建立期限内有效稳定窗口。

延长判定基于该政策绑定的真实下限、候选身份和时间证据，不凭MOS PWM较低或一次普通超时触发。触底后提高非零请求使旧证据失效；保护性零只保留同一候选已有的真实证据。原期限、起算时间、首次检查、phase和失败事实必须保留。

- 未满足两个前提的普通候选继续执行原停止/验收规则。
- 延长不能由传感器、PD/PPS、通信、取消、事件背压或 EEPROM 故障触发；已有安全拒绝始终停热。
- 延长须有明确有限上限，并计入原单目标 `20min` 预算。旧方案 `180s` 是整轮 stage timeout，不能直接当成 Approach 上限。
- 延长不能在试验中偷偷改变候选参数、身份、Hold 入口或温度目标。更换候选仍须在安全 trial boundary 重新 preview 并读回。
- 原期限未达的事实不得被删除，时间不得重置，也不得以伪造 phase 或稳定窗口掩盖超时。
- 延长资格只在原期限首次控制周期检查时决定。原期限后才触底、在 Hold 中申请、或原稳定窗口随后破裂，均不能补发延长资格。原期限内已开始的窗口可以继续完成连续 `10s` 验证；没有此前合法激活的例外时，期限后的窗口破裂必须停止该轮。
- 单个候选失败只能证明该候选在该设备上的实测表现；不得据此断言所有参数都不可行或硬件极限已经被证明。

验收：当前政策只有真实50‰触底才可能延长；历史100‰及混合政策不能冒充50‰证据。期限后触底、Hold中申请、后续升高请求、安全故障均不延长，首次检查只决定一次，上限停止且预算不重置。独立60秒确认和保存身份门禁保持。

### R4：贯通判定、确认与保存

- 原普通路径的时间门禁保持有效。条件延长属于限定例外，不能把全部 `5s/10s` 门槛改成软目标。
- 连续 `10s` 稳定窗口（目标 `±1.5°C`、至少 `3Hz`）、过冲 `<=3°C`、qualified Hold 峰峰值 `<=3°C`、`12s` scout 与完整 `60s` confirm 继续要求真实证据。qualified Hold 沿用既有温度和 phase 观察起点，起点之后的离带样本不得删除。
- 停止、评分、候选比较、确认资格、candidate-ready、seal、confirm-save 和 host 报告验证必须一致；不能只放宽某一环节。
- 符合两个延长前提且满足其余 scout 热指标的候选，按原候选比较与确认流程处理；完整 `60s` 确认通过后，可沿原 candidate-ready、seal 和 confirm-save 流程继续。确认使用同一条件例外政策，原期限未达及延长事实仍须保留。继续取得样本本身不构成通过，也不授权自动写入 EEPROM。
- EEPROM 保存继续绑定 `runId + candidateId + candidateHash + powerClass`，使用既有原子保存/readback receipt；二次确认不重新调优。

验收：普通超时仍失败；条件例外只有两个前提及其余 gate 全部满足才可进入原确认流程，scout 成功仍须完整确认。身份、bank、trace 或持久化不匹配均失败；未获保存授权不得自动保存，取消和故障均停热。覆盖延长后的 scout 成功、确认失败、确认成功及保存身份链，证明例外没有放宽稳定、过冲或保温要求。

- 每个 trial 显示候选范围、effective floor、下限来源、逻辑请求和最终 MOS PWM；缺失字段结构化 unavailable，不能靠当前策略倒填旧数据。
- 在 ledger/bundle/页面明确显示两个触发前提的证据、原期限、允许延长的有限上限、实际延长时间、停止原因及资格处置。字段命名须先与设备事件和 schema 对齐，不能仅在 HTML 临时拼接。
- 保留温度/phase 与 qualified Hold 的区别、完整稳定及保温样本。PPS 电流只表示合同安全 ceiling，不伪造外部实测电流或功率。

验收：正常、失败、缺失证据和条件延长样例均走标准生成路径；选中 trial 的卡片、全部图和 ledger 同步。历史报告不得被重算为通过；真实报告的文件和设备 trace digest 可复核。UI 改动按既有视觉证据流程验证。

### R6：按提交节奏完成 HIL 与参数优化

- 按独立问题提交，英文 Conventional Commits、`--signoff`、保留 hooks；不做单个大提交或捎带无关改动。
- 每个包含固件代码修改的提交，先完成对应软件验证与构建，再按已有精确端口授权烧录该提交的产物并完成相关 HIL；未完成该轮 HIL 不宣称问题修复。
- 固件身份必须同时给出可读版本、提交、构建/产物身份和对应运行记录。烧录后先确认应用启动、授权串口、PPS 合同、有效热模型、100w/pps5a、HOT=LOW 与 heater 安全状态，再开始调优。
- 先验证 60°C 的完整 scout/batch/60 秒确认，再执行默认九目标完整资格范围。诊断范围成功不能代替九目标资格通过；失败 endpoint 不影响独立 endpoint，但依赖该 endpoint 的内部目标继续阻断。
- 60°C 每轮从 `<=35°C` 开始，冷却全程 MOS 断开、风扇全速；终止后继续全速到 `<35°C`。加热风扇使用既有 HOT=LOW；不通过改风扇算法掩盖调优问题。
- 固件80–160°C起点保持目标减40°C；严格高于160°C且不超过200°C时为目标减30°C；严格高于200°C时为目标减20°C。首次、重试、batch与独立确认共用规则，160°C边界保留原120°C起点。起点调整不延迟Warmup制动、不放宽阶段入口或热指标，实际Warmup时长须从样本复核；外部方案保持冻结。原始trial与标准报告记录当时采用的阈值，不改写历史。
- 实机失败保留完整标准报告并据证据修正；完整默认范围、安全失效及匹配的 EEPROM receipt 均具备后才可声称交付资格满足。

验收：每个固件提交有对应精确产物和实机运行证据；软件结果、诊断 HIL、默认资格和保存结果分别记录。端口消失、变化或占用立即停止，不自动换设备。真实 MCU 和外部 HUB 操作继续遵守项目授权边界。

## 计时、上限与候选处置

| 项目 | 实施与验收要求 | 不可放宽的边界 |
| --- | --- | --- |
| 延长计时 | 保留实际 Approach 起止、首次 Warmup 退出、原窗口起点期限及真实稳定窗口起点。只对符合两个前提的候选应用延长；停止、评分、确认与报告必须一致处理延长造成的时间差 | 不重置原计时，不混用参考曲线时长、phase 时长和稳定窗口计时；连续 `10s` 稳定窗口及 `12s/60s` 保温时长不缩水 |
| 有限延长上限 | 依据全部 trial 的下限、升温响应及失败证据确定明确的有限延长参数，在该试验开始前绑定并记录；验证达到上限停止及整轮超时、`20min` 预算约束 | 不启用无限等待，不把 `180s` 直接作为 Approach 上限，不在运行中隐式扩大预算 |
| 资格与保存 | 条件例外满足其余热指标后，沿用原候选比较、完整确认及身份绑定的保存流程；始终记录原期限未达和延长处置 | 不普遍放宽时间门禁，不放宽温度稳定带、过冲、峰峰值或 trace 门禁，不因延长采样自动保存 |

上述规则是已确认的整改范围。有限延长量属于需给出依据并验证的实现参数，不作为额外产品决策或审批阻塞。实现与长期 SPEC 同步后，按 R3/R4 的正向、负向和安全场景验证；超出两个触发条件或改变其余热指标的方案仍属于设计变更。

## 提交顺序与范围外事项

1. 固定本合同并审计 R1，建立基线差异与证据矩阵。
2. 按 R2 修复已证实且不改变算法设计的候选/生效缺陷，每个固件提交完成对应 HIL。
3. 根据完整试验证据确定并验证有限延长参数，同步长期 SPEC，按 R3/R4 实现和验证条件例外及原确认/保存流程。
4. 按 R5 同步事件、schema、标准报告和必要 UI 证据。
5. 按 R6 完成 60°C 确认、九目标调优、安全失效和持久化验证，收口至原交付目标。

无`--engine`的外部主控CLI与其四文件报告保持原行为。3A与5A按[统一控制器决定](../../adr/0017-unified-production-thermal-controller.md)共用生产控制和固件调优流程。板级RTD分压激励独立配置，不冒充用户ADC校准。PD模块、PPS/PowerState语义、`thermal_plant_auto`、用户ADC校准和主动冷却参与加热控制保持边界；其余控制律变化须另行研判。
