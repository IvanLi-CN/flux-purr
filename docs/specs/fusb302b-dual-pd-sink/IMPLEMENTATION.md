# Implementation

## Firmware

- `firmware/src/adapters/pd.rs` defines controller-neutral contract types, source-capability parsing, contractual power calculations, the `20V/3A` performance threshold, and FUSB302BMPX PPS selection within the `5V..28V` absolute guard and live APDO with fixed-PDO fallback.
- `firmware/src/adapters/fusb302b.rs` owns Flux Purr's pure FUSB302B sink policy: PPS and fixed RDO encoding, source-capability decoding, PPS keepalive renewal, and contract state. It does not own FUSB302B register access or FIFO framing. The policy does not authorize heat until `Accept` and `PS_RDY`; detach/reset/reject/wait/fault clears its contract.
- `firmware/src/bin/flux_purr.rs` dispatches production PD traffic through the FUSB302B path only. It requires two stable `0x9x` identity reads plus a readable status bank; all other responses become `unknown` with zero PD writes. Before sink toggle it configures default host current, disables CC measurement, and installs the toggle interrupt mask; after attachment it measures the selected CC pin and installs the receiver interrupt mask. The blocking ESP32-S3 I2C transport is adapted per bounded transaction. EEPROM record restore, record writes, raw maintenance reads/writes, snapshot reads/digest, and verification release the shared bus between bounded chunks and service the FUSB path; no long EEPROM operation can monopolize the PD service loop, and a successful EEPROM commit is never synchronously mirrored to flash.
- FUSB302BMPX currently observes a `5V..21V` PPS APDO with fixed-PDO PWM fallback; calibration requires a qualifying PPS contract. The adapter applies the operational `5.5V` floor and absolute `28V` ceiling before the live APDO boundary, retains every usable APDO for manual and automatic request selection, and never imports the archived controller's `21V` ceiling. A pending FUSB contract starts the normal runtime with heater output interlocked and drains bounded completed PD frames each service turn. Every absent Source Capabilities response remains bounded `Get_Source_Capabilities` retry without a Sink PD reset.
- Automatic heater capacity derives its source voltage interval only from a connected APDO component. When the runtime needs one current ceiling for that interval, it uses the lowest available current at its APDO boundaries, so a higher-current APDO at the top voltage cannot overstate available power at lower requests.
- VIN ADC calibration derives the request current from the APDO covering each voltage in the sweep, including after crossing mixed-APDO boundaries.
- `HeaterPowerBackend` carries terminal thermal-calibration disarm state through PPS and fixed-PDO fallback representations. Capability refresh and fallback-to-PPS rediscovery preserve it; only the explicit manual PPS re-arm path clears it.
- The FUSB302B runtime treats local `RETRY_FAIL`, pending-contract timeout, and partial FIFO timeout as CC-preserving recovery: it clears the active contract and cached capabilities, flushes only the receive FIFO, and returns to bounded `Get_Source_Capabilities` discovery. An active fixed contract sends a bounded `Get_Source_Capabilities` liveness probe every five seconds; an unanswered probe clears that contract and follows the same recovery path. A failed transmit additionally flushes the TX FIFO so an incomplete frame cannot poison the next query. `RETRY_FAIL` recovery precedes every queued receive frame. After `RETRY_FAIL`, it consumes the latch until the next bounded query transmit clears it. Received PD resets also retain Rd and the configured PHY. Any observed low VBUS immediately interlocks heating and invalidates the cached contract; only a `VBUSOK` transition starts the `50ms` continuous-low confirmation before the separate physical-detach path clears polarity/deadlines and re-enters controlled sink toggle discovery. A valid VIN Reading that remains at least `2V` below an active contract for `100ms` applies the same contract interlock and bounded Source_Capabilities recovery; it is suspended during `Accept`/`PS_RDY` and for `500ms` after a request so ordinary PPS transitions can settle. The VIN path never infers VBUS state across MCU power loss. A VBUS-restore guard prevents repeated PHY initialization while VBUS remains absent. A capability refresh that still covers the active contract only updates the cache and does not re-request the same contract. `STATUS0.BC_LVL` cannot prove a Sink detach (`00` can report Ra), so low, active, and unknown status retain Rd and the current PD session.
- Startup configures the active-low backlight before any potentially blocking bus work, initializes the FUSB302B policy with the same elapsed runtime epoch used by every later service turn, and reserves the bounded initial Sink service window before display initialization. Display init and startup-frame flush continue to call the independent PD service cadence while their one-second display timeout remains active. This keeps the initial attachment, source-capability retry, request timeout, and PPS keepalive deadlines comparable across the transition into the main loop.
- The runtime main loop uses a compensating `5ms` PD service deadline ahead of USB/LAN control handling. Each pass consumes at most `256` USB bytes and one complete USB or LAN control command before returning to that deadline gate. It updates `last_pd_observation` from the high-priority service, immediately clears heater output on contract loss, and lets the `50ms` thermal control tick consume the latest observation instead of polling PD itself.
- A source `Reject` or `Wait` before `PS_RDY` cancels the pending request and returns to `WaitingForSourceCapabilities`, allowing the existing bounded re-query path to retry without withdrawing CC. If a later renegotiation is rejected while an active contract exists, the policy returns to `Ready` and preserves that contract.
- Source-capability discovery and recovery use only the FUSB302B sink policy. They do not depend on thermal-tuning state or candidate data.
- When a pending contract becomes ready, the runtime clears any UI or calibration heater arm intent captured before readiness; heating can resume only after a new explicit arm operation.
- `firmware/src/board/s3_frontpanel.rs` reserves `GPIO7` as `PIN_PD_INTERRUPT` and includes it in the active GPIO map.
- Firmware status emits contract metadata separately from the legacy `currentMa` telemetry field. `pdContractCurrentMa` and `pdContractPowerMw` are contractual upper bounds, never a physical-current claim.

## Host And Console

- `flux-purr-devd` preserves and relays the new status fields while retaining its legacy `currentMa` compatibility behavior for existing calibration validation.
- Web transport adapters preserve the fields across devd, serial, and LAN sources.
- The control console presents controller type, contract type, contractual current/power, and guarantee/degraded state in its PD contract status detail.

## Verification

- Firmware adapter tests cover PPS/fixed-RDO framing, PPS renewal, `20V@3A=60W`, `20V@5A=100W`, lower-voltage degraded operation, `Accept`/`PS_RDY`, detach/reset, rejected contracts, and source-capability packet decoding. The upstream crate validates FUSB register access, device identification, PHY configuration, FIFO framing, and full-FIFO receive handling through its public API.
- Control-plane, devd, and Web verification run from repository-native test/build commands.
- Host validation covers FUSB302B identity selection, unknown fail-closed behavior, non-blocking `runtime_ready`, contract-less heater interlock, Dashboard `POWER/WAIT`, EEPROM restore presentation, and PPS policy. Physical HIL remains separately authorized and is not part of this change.
