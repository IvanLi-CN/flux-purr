# Embedded factory thermal baselines before tuning

固件热控调优不能把上传候选文件当作启动前提，因为设备必须在没有设备专属标定数据时仍能安全进入受控加热流程。系统采用两个按供电功率档位选择的完整工厂缺省热控基线，并要求调优在工厂基线或设备标定数据至少有一个可用时才允许启动。

## Decision

- 固件内置且维护两份完整工厂缺省基线：`pps3a`（PPS 3A / 65W）和 `pps5a`（PPS 5A / 100W）。每份基线包含输出曲线或等效输出模型、热模型初值、控制参数以及安全边界。
- 固件依据已确认的供电功率档位选择基线。供电档位无法确认时禁止启动调优和加热，不猜测功率档位，也不回退到另一份基线。
- 有效的设备加热曲线或热模型标定数据优先用于解析调优起点；缺少设备专属标定数据时使用对应的工厂缺省基线。两者都不可用时返回 `thermal_parameters_unavailable`，保持加热输出关闭。
- 调优结果先保存在 RAM 中作为候选。只有调优发起者明确确认保存后，结果才替换对应功率档位的持久化配置；停止、断电或失败保留原配置。
- 同一设备同时只能有一个调优运行。其他客户端仍可读取状态，但所有写操作都被拒绝或置灰；任一已认证客户端都可以执行幂等的停止操作，只有调优发起者可以确认保存。

## Considered Options

- **要求每次上传候选文件**：拒绝，因为没有候选文件时设备无法开始调优，形成不必要的鸡蛋问题。
- **只内置一份通用基线**：拒绝，因为 3A 与 5A 的可用功率和安全边界不同。
- **按每块加热板内置独立基线**：拒绝，因为加热板差异应由设备标定和热模型吸收，固件不应随硬件实例数量线性膨胀。
- **功率档位未知时猜测或使用 3A**：拒绝，因为错误的功率档位会让输出模型和安全边界失配。

## Consequences

- 固件发布物必须携带两份经过验证的完整工厂基线；结构体默认值或空 profile 不能被视为可运行基线。
- Web、devd、USB 和 LAN 入口共享同一套“参数来源解析、候选预览、确认保存和停止”语义。
- 加热曲线标定负责电气输出修正，热模型和实际调优负责热惯性、散热和过冲等动态差异；工厂基线提供安全可运行的初始状态。
- 缺少参数时，界面必须解释为热控参数不可用，不得显示为网络断开、配对失败或固件不支持。
